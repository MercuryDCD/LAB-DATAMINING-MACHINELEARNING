\section{Essential Concepts (Class Notes \& Lab Context)}

Exploratory Data Analysis (EDA) is the systematic audit of a dataset before any model training. As emphasized in the course slides: \textit{``Better data quality $\implies$ better results (garbage-in, garbage-out)''}.

\subsection{Attribute Types \& Permitted Operations (Stevens, 1946)}
From the lecture slides (\textit{The Data}, slide 5), attributes are categorized into four levels. The operations permitted on each level are incremental:

\begin{definitionbox}[Data Types Summary (Prof. Sartori's Slides)]
\begin{itemize}[leftmargin=*]
    \item \textbf{Nominal (Categorical):} Values are distinct labels ($=, \neq$). Operations: Mode, frequency, contingency tables, $\chi^2$ test. \textit{Examples:} \lstinline!class! (Iris species), \lstinline!postcode!.
    \item \textbf{Ordinal (Categorical):} Values provide an intrinsic ranking ($<, >$). Operations: Median, percentiles, rank correlation. \textit{Example:} \lstinline!tier! ($\text{Basic} < \text{Silver} < \text{Gold}$).
    \item \textbf{Interval (Numerical):} Differences are meaningful, but zero is arbitrary (no true physical zero). Operations: Mean, standard deviation, Pearson correlation, $t$-tests. \textit{Examples:} Temperature in $^\circ\text{C}$, calendar dates.
    \item \textbf{Ratio (Numerical):} Possesses a true, univocal physical zero ($0 = \text{absence}$). Operations: All mathematical operations, ratios, percentage variations, geometric mean. \textit{Examples:} Lengths, \lstinline!annual_spend!, counts.
\end{itemize}
\textbf{Special Rule for Identifiers (\textit{Slide 11}):} \lstinline!customer_id! is an identifier. Identifiers are \textit{``useful for data manipulation, not for analysis''}. They must always be excluded from feature matrices to prevent artificial memorization.
\end{definitionbox}

\subsection{Data Quality: Sentinels, Outliers \& Informative Missingness}
Real-world data is never clean. Three specific phenomena from the lecture slides and lab:
\begin{enumerate}[leftmargin=*]
    \item \textbf{Nulls in Disguise (Sentinel Values, \textit{Slide 14}):} Storing $0$ or $999$ when information is missing or not applicable (e.g., $999$ in \lstinline!days_since_last_buy! for customers who never bought, or $0$ in \lstinline!age!). Leaving them as numbers violently distorts means and standard deviations.
    \item \textbf{Outliers: Noise vs. Rare Processes (\textit{Slide 26--28}):} Outliers are points considerably different from the rest. They can stem from corrupted data (noise) OR genuine rare events/processes. In customer data, high spenders are legitimate business assets (``whales''), not errors.
    \item \textbf{Informative Missingness:} Missing data is not always accidental. If the churn rate among missing values is substantially higher ($23\%$ vs $9\%$), the absence of data is itself a powerful predictive signal.
    \item \textbf{Simpson's Paradox (Confounders):} An aggregate correlation across the entire dataset can be positive even when the correlation within every subgroup is zero or negative. A confounding variable (like \lstinline!tier!) drives both attributes independently.
\end{enumerate}

% 2. THE 7-STEP EDA CHECKLIST
% ==============================================================================
\section{The 7-Step EDA Checklist}

The standard EDA protocol followed across every laboratory:
\begin{enumerate}[leftmargin=*]
    \item \textbf{Dataset Kind \& Types:} Inspect file format, delimiter, headers, column types. Isolate identifiers.
    \item \textbf{Summaries \& Distributions:} Compute five-number summaries (\lstinline!describe()!); inspect symmetry and plot histograms with multiple bin widths.
    \item \textbf{Missing Values Audit:} Count \lstinline!NaN! values and evaluate whether missingness correlates with the target.
    \item \textbf{Data Quality Checks:} Search for sentinel codes ($999, 0$), impossible values ($\le 0$), Tukey IQR outliers, and duplicated records.
    \item \textbf{Target Analysis:} Check class balance (\lstinline!value_counts(normalize=True)!) and evaluate the trivial majority model baseline.
    \item \textbf{Feature $\times$ Target Associations:} Bivariate plots (box plots by class, scatter plots with hue, stratified correlations).
    \item \textbf{Findings \& Preparation Log (EDA Log):} Record every finding, the supporting evidence, and the resulting engineering decision.
\end{enumerate}

\section{Practical Code Recipes: How, Why \& What For}

\subsection{Recipe 1: Safe Working Copy \& Cardinality Audit}
\begin{lstlisting}[language=Python]
# HOW:
df = pd.read_csv("nordicmart_customers.csv")
customers = df.copy()  # Never mutate the raw table df!

print(customers.nunique())
\end{lstlisting}
\begin{itemize}[leftmargin=*]
    \item \textbf{Why:} Keeping \lstinline!df! untouched ensures that raw data integrity can be verified at any point with unit assertions. Calling \lstinline!nunique()! exposes constant columns (cardinality 1) and unique IDs (cardinality $= N$).
    \item \textbf{What For:} Immediately flags \lstinline!customer_id! (3000 distinct) as an identifier to drop from features, and \lstinline!postcode! (1 distinct value: 40100) as a zero-variance column to remove.
\end{itemize}

\subsection{Recipe 2: Enforcing Ordered Categoricals \& String Types}
\begin{lstlisting}[language=Python]
# HOW:
customers["postcode"] = (
    customers["postcode"]
    .astype("string")
    .str.replace(r"\.0$", "", regex=True)
)
customers["tier"] = pd.Categorical(
    customers["tier"],
    categories=["Basic", "Silver", "Gold"],
    ordered=True
)
\end{lstlisting}
\begin{itemize}[leftmargin=*]
    \item \textbf{Why:} Pandas reads nullable integer columns as \lstinline!float64!, giving postcodes like \texttt{40100.0}. We cast to string and strip the decimal. Setting \lstinline!ordered=True! guarantees that plots and sort operations follow the domain hierarchy rather than alphabetical order (\texttt{Basic < Gold < Silver}).
    \item \textbf{What For:} Prevents category order errors in bar charts and prepares ordinal features for monotonic encoding.
\end{itemize}

\subsection{Recipe 3: Catching Sentinels (``Nulls in Disguise'') \& Adding Indicator Flags}
\begin{lstlisting}[language=Python]
# HOW:
# 1. Create a binary indicator flag BEFORE recoding
customers["never_bought"] = (customers["days_since_last_buy"] == 999).astype(int)

# 2. Recode sentinel codes to NaN using functional replacement
customers["days_since_last_buy"] = customers["days_since_last_buy"].replace(999, np.nan)
customers["age"] = customers["age"].replace(0, np.nan)
\end{lstlisting}
\begin{itemize}[leftmargin=*]
    \item \textbf{Why:} The value 999 is a sentinel code for customers who never purchased; 0 in age is a placeholder for unknown age. Avoid \lstinline!inplace=True! because it is deprecated in modern pandas and triggers chained assignment warnings.
    \item \textbf{What For:} Replaces artificial numbers with proper missing values so that recency averages drop from 69.5 to 50.2 days (unskewed), while \lstinline!never_bought! retains the business signal for the classifier.
\end{itemize}

\subsection{Recipe 4: Diagnosing Informative Missingness (MNAR)}
\begin{lstlisting}[language=Python]
# HOW:
print(customers.groupby(customers["web_sessions_month"].isna())["churned"].mean())
print(customers.groupby(customers["age"].isna())["churned"].mean())
\end{lstlisting}
\begin{itemize}[leftmargin=*]
    \item \textbf{Why:} By grouping the target by the boolean mask of \lstinline!.isna()!, we test whether the probability of missingness depends on the target class.
    \item \textbf{What For:} 
    \begin{itemize}
        \item \lstinline!web_sessions_month!: Missing churn rate is \textbf{23.1\%} vs \textbf{9.6\%} for observed. This is \textbf{informative missingness (MNAR)}. We must keep a missingness indicator flag before imputation.
        \item \lstinline!age!: Missing churn rate is \textbf{12.6\%} vs \textbf{11.9\%} observed. This is \textbf{random missingness (MCAR)}. Standard median imputation without an extra flag is completely safe.
    \end{itemize}
\end{itemize}

\subsection{Recipe 5: Tukey IQR Outlier Auditing with Subgroup Conditioning}
\begin{lstlisting}[language=Python]
# HOW:
q1 = customers["annual_spend"].quantile(0.25)
q3 = customers["annual_spend"].quantile(0.75)
iqr = q3 - q1
upper_fence = q3 + 1.5 * iqr

outliers = customers[customers["annual_spend"] > upper_fence]
print(f"Total candidate outliers: {len(outliers)}")
print(outliers["tier"].value_counts(sort=False))

# Subgroup boxplot
customers.boxplot(column="annual_spend", by="tier")
plt.suptitle("")
plt.show()
\end{lstlisting}
\begin{itemize}[leftmargin=*]
    \item \textbf{Why:} Global Tukey fences ($> \$1843.24$) flag 204 points as candidate outliers. However, breaking down by tier shows that 131 belong to Gold and 63 to Silver.
    \item \textbf{What For:} Prevents the catastrophic mistake of deleting high-value customers. The boxplot proves that spend is conditioned by tier. They are legitimate high spenders (``whales''), not noisy measurement errors.
\end{itemize}

\subsection{Recipe 6: Target Imbalance Audit \& Trivial Model Baseline}
\begin{lstlisting}[language=Python]
# HOW:
print(customers["churned"].value_counts(normalize=True))

actual = customers["churned"]
predicted = pd.Series(0, index=customers.index) # Trivial model: always predict '0'

print(pd.crosstab(actual, predicted, rownames=["actual"], colnames=["predicted"]))
accuracy = (actual == predicted).mean()
recall = ((actual == 1) & (predicted == 1)).sum() / (actual == 1).sum()
print(f"Accuracy: {accuracy:.1%}, Recall: {recall:.1%}")
\end{lstlisting}
\begin{itemize}[leftmargin=*]
    \item \textbf{Why:} Demonstrates the Base Rate Fallacy. The trivial model achieves 88\% accuracy simply by predicting that nobody churns.
    \item \textbf{What For:} Establishes that accuracy is useless for this project. The final machine learning model must be evaluated on minority class recall, $F_1$-score, or PR-AUC.
\end{itemize}

\subsection{Recipe 7: Bivariate Feature Selection (Boxplots per Class)}
\begin{lstlisting}[language=Python]
# HOW:
fig, axs = plt.subplots(1, 2, figsize=(12, 4))
sns.boxplot(data=customers, x="churned", y="days_since_last_buy", ax=axs[0])
axs[0].set_title("Recency by Churn")

sns.boxplot(data=customers, x="churned", y="tickets_90d", ax=axs[1])
axs[1].set_title("Tickets by Churn")
plt.tight_layout()
plt.show()
\end{lstlisting}
\begin{itemize}[leftmargin=*]
    \item \textbf{Why:} Boxplots of features grouped by the binary target visually reveal separation between class distributions.
    \item \textbf{What For:} \lstinline!days_since_last_buy! shows clear separation (churners have much higher recency; promising feature), whereas \lstinline!tickets_90d! shows almost complete box overlap (weak standalone discriminator).
\end{itemize}

\subsection{Recipe 8: Stratified Correlation Matrix (Catching Simpson's Paradox)}
\begin{lstlisting}[language=Python]
# HOW:
# 1. Pearson and Spearman on numeric features ONLY (exclude customer_id)
numeric_cols = ["age", "annual_spend", "days_since_last_buy", "web_sessions_month", "tickets_90d", "churned"]
sns.heatmap(customers[numeric_cols].corr(method="pearson"), annot=True, fmt=".2f", cmap="coolwarm")
plt.show()

# 2. Check for confounders: overall vs intra-tier correlation
print("Overall corr:", customers["annual_spend"].corr(customers["web_sessions_month"]))
for tier, group in customers.groupby("tier", observed=False):
    print(f"Tier {tier:6s}:", group["annual_spend"].corr(group["web_sessions_month"]))
\end{lstlisting}
\begin{itemize}[leftmargin=*]
    \item \textbf{Why:} Overall correlation is $+0.37$, suggesting that website visits cause spending. But inside each tier, correlation drops to $0.04$ (Basic), $0.04$ (Silver), and $-0.00$ (Gold).
    \item \textbf{What For:} Uncovers \textbf{Simpson's Paradox}. Tier is a confounding variable: Gold members spend more and browse more independently. Web sessions do NOT drive spending.
\end{itemize}

% ==============================================================================
\section{Key Pitfalls \& Practical Traps}

\begin{enumerate}[leftmargin=*]
    \item \textbf{Evaluating Duplicates on a Single Column instead of Full Rows:}\\
    \textit{Anti-pattern:} \lstinline!iris["col"].duplicated().sum()! counts recurring values in one feature (completely normal).\\
    \textit{Correct practice:} \lstinline!iris.duplicated().sum()! checks for identical samples across all features simultaneously.
    
    \item \textbf{Including Identifiers in Heatmaps and Models:}\\
    \textit{Anti-pattern:} Passing \lstinline!customer_id! to \lstinline!corr()! or decision trees creates spurious correlation with sequential IDs and risks severe overfitting. Always filter out IDs.

    \item \textbf{Relying on a Single Histogram Bin Width:}\\
    \textit{Anti-pattern:} Plotting \lstinline!petal_length! with 5 bins makes it look like a single unimodal distribution.\\
    \textit{Correct practice:} Always compare multiple bin widths (e.g. 5, 15, 40) or use the adaptive Freedman–Diaconis rule (\lstinline!bins="fd"!). In Iris, 15 bins clearly reveals the separate cluster of \textit{setosa}.

    \item \textbf{Destructive In-Place Data Imputation:}\\
    \textit{Anti-pattern:} Imputing \lstinline!web_sessions_month! with the column median without generating \lstinline!web_sessions_isna! destroys the strongest churn predictor in the dataset.
\end{enumerate}
