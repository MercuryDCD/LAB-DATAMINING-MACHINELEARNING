\section{Essential Concepts (Class Notes \& Lab Context)}

Exploratory Data Analysis (EDA) is the iterative auditing phase that precedes all modeling. As emphasized in the course slides: \textit{``Data are never perfect. Better data quality $\implies$ better results (garbage-in, garbage-out)''}.

\subsection{Why Look Before Modeling? (Anscombe's Warning)}
As demonstrated by \textbf{Anscombe's Quartet} (\textit{Lecture 6, slides 8--9}): four distinct datasets can possess identical summary statistics (mean $9.0$, variance $11.0$, Pearson correlation $r = 0.816$, and regression line $y = 3.0 + 0.5x$), yet exhibit completely different underlying structures (linear, parabolic, regression with outlier leverage, vertical cluster). Summary statistics alone are blind; visual inspection is mandatory.

\subsection{Attribute Types \& Permitted Operations (Stevens, 1946)}
From \textit{Lecture 6, slides 19--22}, attribute types form a strict hierarchy where operations are cumulative:

\begin{definitionbox}[Stevens' Typology in Machine Learning]
\begin{itemize}[leftmargin=*]
    \item \textbf{Nominal (Categorical):} Distinguishes equality only ($=, \neq$). Operations: Mode, frequency counts, $\chi^2$ contingency. \textit{Examples:} Iris \lstinline!class!, \lstinline!postcode!.
    \item \textbf{Ordinal (Categorical):} Provides a transitive ranking ($<, >$). Operations: Median, percentiles, rank order. \textit{Example:} Customer \lstinline!tier! ($\text{Basic} < \text{Silver} < \text{Gold}$).
    \item \textbf{Interval (Numerical):} Differences are meaningful, but zero is arbitrary (no physical zero). Operations: Addition, subtraction, mean, standard deviation, Pearson $r$. \textit{Examples:} Temperature in $^\circ\text{C}$, calendar dates.
    \item \textbf{Ratio (Numerical):} True physical zero ($0 \implies$ total absence). Operations: All mathematical operations, ratios, percentage variations, geometric mean. \textit{Examples:} Physical lengths, \lstinline!annual_spend!, discrete counts.
\end{itemize}
\textbf{Rule for Identifiers (\textit{Slide 23}):} \lstinline!customer_id! is an identifier. Identifiers are \textit{``useful for data manipulation, not for analysis''}. They must be removed from the feature matrix to prevent data leakage and trivial memorization.
\end{definitionbox}

\subsection{Data Quality: Sentinels, Outliers \& Informative Missingness}
\begin{enumerate}[leftmargin=*]
    \item \textbf{Nulls in Disguise (Sentinel Codes, \textit{Slide 41--42}):} A widespread database habit is encoding missing or non-applicable data as numeric constants (e.g., $999$ in \lstinline!days_since_last_buy! for customers who never bought, or $0$ in \lstinline!age!). Leaving $999$ as a number artificially skews the mean from $50.2$ to $69.5$ days.
    \item \textbf{Outliers: Noise vs. Rare Processes (\textit{Slides 46--49}):} Outliers are values considerably different from the rest. They stem from either \textit{corrupted data (noise)} or \textit{valid rare events}. In customer analytics, high spenders are legitimate high-value customers (``whales''), not errors. Deleting them throws away the most valuable commercial segment.
    \item \textbf{Informative Missingness (\textit{Slide 44}):} Missing data is not always random. When missingness in \lstinline!web_sessions_month! correlates with a $23.1\%$ churn rate (vs $9.6\%$ when observed), the absence of data is an informative behavioral predictor (MNAR) that requires an indicator flag.
    \item \textbf{Simpson's Paradox \& Confounders (\textit{Slides 63--64}):} An aggregate correlation can reverse or disappear when data is conditioned on a subgroup. In NordicMart, spend and web sessions show $r = +0.37$ overall, but within every tier $r \approx 0.00$. \lstinline!tier! is a confounder driving both attributes independently.
    \item \textbf{Class Imbalance \& The Trivial Model Trap (\textit{Slides 51--52}):} When the target is imbalanced ($88\%$ non-churners vs $12\%$ churners), a trivial model predicting ``stays'' for all customers achieves $88\%$ accuracy but detects $0\%$ of churners. Accuracy is deceptive; evaluation requires Precision, Recall, and PR-AUC.
\end{enumerate}

\subsection{Notebook Engineering Good Practices (\textit{Lecture 7, slides 5--8})}
\begin{itemize}[leftmargin=*]
    \item \textbf{Hidden State Danger:} The execution state lives in the Python kernel process, not in the notebook JSON file. Out-of-order cell execution causes non-reproducible bugs. Always verify with \textbf{Kernel $\to$ Restart \& Run All}.
    \item \textbf{Raw Data Immutability:} The raw dataset (\lstinline!df!) must never be modified in-place; all transformations belong exclusively in working copies (\lstinline!customers!).
\end{itemize}

\section{The 7-Step EDA Checklist \& Visualization Matrix}

\subsection{The Protocol (Lecture 6, Slide 72)}
\begin{enumerate}[leftmargin=*]
    \item \textbf{Kind \& Types:} Inspect dimensions, data types, and isolate unique identifiers.
    \item \textbf{Univariate Summaries:} Check distribution shapes, mean vs median symmetry, and histogram binning.
    \item \textbf{Missing Values:} Calculate missingness percentages and evaluate if missingness predicts the target.
    \item \textbf{Data Quality:} Unmask sentinel codes, impossible values, Tukey IQR outliers, and duplicated rows.
    \item \textbf{Target Analysis:} Inspect class balance and benchmark against the trivial majority classifier.
    \item \textbf{Bivariate Associations:} Feature $\times$ Target separation, correlation matrices, and confounder checks.
    \item \textbf{EDA Log:} Record every action in the 4-column log (\textbf{Finding $\to$ Evidence $\to$ Decision $\to$ Status}).
\end{enumerate}

\section{Practical Code Recipes: How, Why \& What For}

\subsection{Recipe 1: Safe Working Copy \& Cardinality Audit}
\begin{lstlisting}[language=Python]
# HOW:
df = pd.read_csv("nordicmart_customers.csv")
customers = df.copy()  # Raw table remains strictly immutable!

print(customers.nunique())
\end{lstlisting}
\begin{itemize}[leftmargin=*]
    \item \textbf{Why:} Keeping \lstinline!df! untouched enables unit assertions at the end of the pipeline. Calling \lstinline!nunique()! exposes identifiers (cardinality $= N$) and zero-variance constants (cardinality $\le 1$).
    \item \textbf{What For:} Flags \lstinline!customer_id! (3000 distinct) as an identifier to drop from features, and \lstinline!postcode! (only 1 value: 40100) as a constant feature to remove.
\end{itemize}

\subsection{Recipe 2: Enforcing Ordered Categoricals \& String Types}
\begin{lstlisting}[language=Python]
# HOW:
customers["postcode"] = (
    customers["postcode"]
    .astype("string")
    .str.replace(r"\.0$", "", regex=True)
)
customers["tier"] = pd.Categorical(
    customers["tier"],
    categories=["Basic", "Silver", "Gold"],
    ordered=True
)
\end{lstlisting}
\begin{itemize}[leftmargin=*]
    \item \textbf{Why:} Pandas coerces integer columns with missing values to \lstinline!float64! (yielding \texttt{40100.0}). We cast to text without decimals. Setting \lstinline!ordered=True! guarantees that sorting and plots respect domain hierarchy rather than alphabetical order.
    \item \textbf{What For:} Prevents category inversion in visualizations and prepares ordinal data for monotonic encoding.
\end{itemize}

\subsection{Recipe 3: Catching Sentinels (``Nulls in Disguise'') \& Adding Indicator Flags}
\begin{lstlisting}[language=Python]
# HOW:
# 1. Create a binary indicator flag BEFORE recoding
customers["never_bought"] = (customers["days_since_last_buy"] == 999).astype(int)

# 2. Recode sentinel codes to NaN using functional replacement
customers["days_since_last_buy"] = customers["days_since_last_buy"].replace(999, np.nan)
customers["age"] = customers["age"].replace(0, np.nan)
\end{lstlisting}
\begin{itemize}[leftmargin=*]
    \item \textbf{Why:} The value $999$ represents customers who never purchased; $0$ in age represents unrecorded age. Avoid deprecated \lstinline!inplace=True! to prevent chained assignment warnings.
    \item \textbf{What For:} Removes artificial numbers so recency mean drops from $69.5$ to $50.2$ days (unskewed), while \lstinline!never_bought! preserves the behavioral signal for the classifier.
\end{itemize}

\subsection{Recipe 4: Diagnosing Informative Missingness (MNAR)}
\begin{lstlisting}[language=Python]
# HOW:
print(customers.groupby(customers["web_sessions_month"].isna())["churned"].mean())
print(customers.groupby(customers["age"].isna())["churned"].mean())
\end{lstlisting}
\begin{itemize}[leftmargin=*]
    \item \textbf{Why:} Grouping the target by the boolean mask of \lstinline!.isna()! tests whether missingness predicts the outcome.
    \item \textbf{What For:} 
    \begin{itemize}
        \item \lstinline!web_sessions_month!: Missing churn rate is \textbf{23.1\%} vs \textbf{9.6\%} observed. This is \textbf{informative missingness (MNAR)}. We must retain a missingness indicator flag prior to imputation.
        \item \lstinline!age!: Missing churn rate is \textbf{12.6\%} vs \textbf{11.9\%} observed. This is \textbf{random missingness (MCAR)}. Standard median imputation without an extra flag is unbiased.
    \end{itemize}
\end{itemize}

\subsection{Recipe 5: Tukey IQR Outlier Auditing with Subgroup Conditioning}
\begin{lstlisting}[language=Python]
# HOW:
q1 = customers["annual_spend"].quantile(0.25)
q3 = customers["annual_spend"].quantile(0.75)
iqr = q3 - q1
upper_fence = q3 + 1.5 * iqr

outliers = customers[customers["annual_spend"] > upper_fence]
print(f"Total candidate outliers: {len(outliers)}")
print(outliers["tier"].value_counts(sort=False))

# Subgroup boxplot
customers.boxplot(column="annual_spend", by="tier")
plt.suptitle("")
plt.show()
\end{lstlisting}
\begin{itemize}[leftmargin=*]
    \item \textbf{Why:} Global Tukey fences ($> \$1843.24$) flag 204 points as candidate outliers. However, breaking down by tier shows that 131 belong to Gold ($64\%$).
    \item \textbf{What For:} Prevents deleting high-value customers. The boxplot proves spend is conditioned by tier. They are legitimate high spenders (``whales''), not noisy measurement errors.
\end{itemize}

\subsection{Recipe 6: Target Imbalance Audit \& Trivial Model Baseline}
\begin{lstlisting}[language=Python]
# HOW:
print(customers["churned"].value_counts(normalize=True))

actual = customers["churned"]
predicted = pd.Series(0, index=customers.index) # Trivial model: always predict '0'

print(pd.crosstab(actual, predicted, rownames=["actual"], colnames=["predicted"]))
accuracy = (actual == predicted).mean()
recall = ((actual == 1) & (predicted == 1)).sum() / (actual == 1).sum()
print(f"Accuracy: {accuracy:.1%}, Recall: {recall:.1%}")
\end{lstlisting}
\begin{itemize}[leftmargin=*]
    \item \textbf{Why:} Demonstrates the Base Rate Fallacy. The trivial model achieves 88\% accuracy by predicting that nobody churns.
    \item \textbf{What For:} Establishes that accuracy is useless for this project. Models must be evaluated using minority-class Recall, $F_1$-score, or PR-AUC.
\end{itemize}

\subsection{Recipe 7: Bivariate Feature Selection (Boxplots per Class)}
\begin{lstlisting}[language=Python]
# HOW:
fig, axs = plt.subplots(1, 2, figsize=(12, 4))
sns.boxplot(data=customers, x="churned", y="days_since_last_buy", ax=axs[0])
axs[0].set_title("Recency by Churn")

sns.boxplot(data=customers, x="churned", y="tickets_90d", ax=axs[1])
axs[1].set_title("Tickets by Churn")
plt.tight_layout()
plt.show()
\end{lstlisting}
\begin{itemize}[leftmargin=*]
    \item \textbf{Why:} Boxplots of continuous features grouped by the binary target visually reveal class separability.
    \item \textbf{What For:} \lstinline!days_since_last_buy! shows clear separation (promising predictive feature), whereas \lstinline!tickets_90d! displays heavy interquartile overlap (weak standalone discriminator).
\end{itemize}

\subsection{Recipe 8: Stratified Correlation Matrix (Catching Simpson's Paradox)}
\begin{lstlisting}[language=Python]
# HOW:
# 1. Pearson and Spearman on numeric features ONLY (exclude customer_id)
numeric_cols = ["age", "annual_spend", "days_since_last_buy", "web_sessions_month", "tickets_90d", "churned"]
sns.heatmap(customers[numeric_cols].corr(method="pearson"), annot=True, fmt=".2f", cmap="coolwarm")
plt.show()

# 2. Check for confounders: overall vs intra-tier correlation
print("Overall corr:", customers["annual_spend"].corr(customers["web_sessions_month"]))
for tier, group in customers.groupby("tier", observed=False):
    print(f"Tier {tier:6s}:", group["annual_spend"].corr(group["web_sessions_month"]))
\end{lstlisting}
\begin{itemize}[leftmargin=*]
    \item \textbf{Why:} Overall correlation is $+0.37$, suggesting that website visits drive spending. Within each tier, correlation drops to $0.04$ (Basic), $0.04$ (Silver), and $-0.00$ (Gold).
    \item \textbf{What For:} Uncovers \textbf{Simpson's Paradox}. Tier is a confounding variable: Gold members independently spend more and browse more. Web sessions do NOT cause spending.
\end{itemize}

\section{Key Pitfalls \& Practical Traps}

\begin{enumerate}[leftmargin=*]
    \item \textbf{Evaluating Duplicates on a Single Column instead of Full Rows:}\\
    \textit{Anti-pattern:} \lstinline!iris["col"].duplicated().sum()! counts recurring values in one feature (completely normal).\\
    \textit{Correct practice:} \lstinline!iris.duplicated().sum()! checks for identical samples across all features simultaneously.
    
    \item \textbf{Including Identifiers in Heatmaps and Models:}\\
    \textit{Anti-pattern:} Passing \lstinline!customer_id! to \lstinline!corr()! or decision trees creates spurious correlation with sequential IDs and causes severe overfitting. Always filter out IDs.

    \item \textbf{Relying on a Single Histogram Bin Width:}\\
    \textit{Anti-pattern:} Plotting \lstinline!petal_length! with 5 bins makes it look like a single unimodal distribution.\\
    \textit{Correct practice:} Always compare multiple bin widths (e.g. 5, 15, 40) or use the adaptive Freedman–Diaconis rule (\lstinline!bins="fd"!). In Iris, 15 bins clearly reveals the separate cluster of \textit{setosa}.

    \item \textbf{Destructive In-Place Data Imputation:}\\
    \textit{Anti-pattern:} Imputing \lstinline!web_sessions_month! with the column median without generating \lstinline!web_sessions_isna! destroys the strongest churn predictor in the dataset.
\end{enumerate}
